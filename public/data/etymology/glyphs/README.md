# Lazy etymology shards

Files `<block>.json` are generated by `python scripts/import-etymology.py --write`.
The block is the lowercase hexadecimal Unicode code point shifted right by 8,
padded to four digits: 古 U+53E4 is in `0053.json`. Each shard's `characters` object
uses exact glyph keys, not inferred variants or catalogue IDs.

The index in [../index.json](../index.json) routes current record IDs and
family-qualified radical forms to shards and records SHA-256/byte lengths.
Source-only forms can be read from their deterministic block when referenced by
a graphical occurrence, but must not become invented catalogue records/links.
Numbered tokens and unsupported notation never use this lexical lookup.

Each shard contains root dataset metadata and full source notices, original text
entries, exact target associations, unreviewed written-form suggestions, source
comparison coverage and optional BabelStone textual occurrence evidence.
Shuowen entries additionally carry separate unreviewed English AI drafts, bound
to their original Chinese text hashes; the original `text` remains unchanged.
The shared [schema](../etymology.schema.json) defines the envelope and the
[frontend guide](../README.md) defines status/display rules.

The browser should fetch only the needed shard after an etymology request. The
only application consumer is `src/lib/etymology.ts`. Do not hand-edit generated shards, import
them into page bundles or use their structural references as stroke bindings.
