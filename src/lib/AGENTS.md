- matchesRecordedGSource may treat two codepoints as one part only through radical-context's sameContextualForm (same family and recorded form in the owner character) or a radical-file alias of the same family form (breakdownDisplayGlyph, e.g. ⺝ → 月), so a look-alike radical codepoint never shows a duplicate breakdown while unrelated glyphs stay distinct.
- radical-contextual-identity.ts applies the audit's reviewed contextualIdentity (extracted by scripts/import-radical-contextual-identities.py into src/data) only for an exact family + form key + recorded glyph, so a variant like #96's jade 王 never shows the look-alike character's reading while standalone records stay untouched; its card intro is composed by identitySummary from those fields, so every reviewed look-alike case reads the same.
- Glyphs missing from Hanzi Writer Data may use only outlines listed in scripts/import-supplementary-outlines.py (AnimCJK SVGs flipped back to Hanzi Writer space, stroke count checked against the radical file): the same exact code point, or an owner-reviewed look-alike link; loadStrokeGeometry serves them with provenance and an exact flag, so Practice names the real source and no look-alike outline is substituted automatically.
- component-families.ts decides which Components records share a radical-family card (one recorded family, not a sourced shared form, matching Kangxi identity, same recorded sound or no own reading); grouping is presentation only, the card ranks by its best form and every form keeps its own record, rank and bookmark, so look-alikes with their own sound (王, 巳, 纟) are never merged.
- Per-reading meanings come only from owner-reviewed catalog.json readingMeanings, applied by catalog-store readingMeanings only while the character row still records the reviewed combined meaning and readings, so no sense is paired with a reading by inference. One-line cards (grid, search, flashcards) use glyph-presentation cardMeaning, joining those meanings with " / " in the record's reading order only when the record has exactly the reviewed readings, so a card never pairs a multi-reading pinyin with one reading's senses.
- Owner-approved exception to the root fail-closed stroke rule: practiceStrokeNames (radical-strokes.ts) lets Practice show a derived radical sequence only when its length matches the outline, flagged so the Strokes heading labels it "Derived · unverified"; strokeNames() and reference cards still treat derived as unrecorded.
- Breakdown tiles draw a token through breakdownDisplayGlyph (radical-identities.ts): only a code the radical file records as an alias of a family form (⺝ → 月) shows that form's character, so both source trees draw one picture while trees, links and identities keep the source token.
- Meaning senses owned by a related character come only from owner-reviewed catalog.json meaningPointers (meaning-pointers.ts): applied only while the row still records the reviewed text and the target is in the recorded related-characters set, rendered as a "→ 乾" link beside the unchanged sense (per reading line when a readingMeanings split exists), so recorded meanings are never rewritten. Reading additions follow catalog.json readingRevisions with their dictionary source.
